Part A — Environment

You do not need to install anything. Use Google Colab.

  1. https://colab.research.google.com, sign in with your Purdue account.
  2. File → New notebook.
  3. Run:
!pip install yfinance --quiet
import yfinance as yf, pandas as pd
print("yfinance", yf.__version__, "| pandas", pd.__version__)

Two version numbers and no red text. If you see red, paste the entire error into your AI and ask what it means — do not ask it to fix the code yet. Understanding the error is the skill.

You are not expected to write Python from scratch in this course. You are expected to read code, say what it does, find the error in it, and check that it does what it claims.

Part B — Generation 1: start the access requests

These are slow. Start them now.

WRDS — the research platform. Purdue routes access through the library; note that WRDS accounts are typically for graduate students and faculty, which includes you. Expect an approval queue.

LSEG Workspace — available to all Purdue users. Register with your @purdue.edu address. Registration is handled by LSEG, not Purdue, and the welcome mail sometimes lands in spam.

Start from the Purdue Libraries business databases guide — https://guides.lib.purdue.edu/refinitivworkspace for LSEG, and the business databases list for the rest.

Optional, worth attempting: S&P Capital IQ and PitchBook. Both are lookup tools rather than pipelines — their licences restrict bulk export, so no lab depends on them.

Not in this course: Bloomberg. It is terminal-bound and cannot be scripted for coursework. Knowing why is the capability; nothing here needs it.

For each attempt, record: link used, date and time, resulting status, remaining blocker, and one sentence on what you learned about what that platform is for.

A denial or a pending queue costs you nothing. The documented attempt is what is graded.

If you are blocked: contact Purdue business data library support, then the Libraries help channels, then the instructor — during prework, not the night before the lab.

Part C — Generation 2: get a key and pull something

This is the half that works immediately.

SEC EDGAR needs no account at all. Run this now:

import json, urllib.request

req = urllib.request.Request(
    "https://data.sec.gov/submissions/CIK0000320193.json",
    headers={"User-Agent": "your.name@purdue.edu"})   # a real contact is required
d = json.load(urllib.request.urlopen(req))
print(d["name"], d["tickers"])

Then get one API key from a Generation 2 source in [the source register](../sources.html) — Financial Datasets and Databento both have free tiers or credits. Pull something with it.

Check the cost page before you sign up, and do not spend money. Nothing in this course requires payment. If a source wants a card before it will issue a key, skip it and use another.

Record how long Part C took compared with Part B. Bring both numbers.

Part D — Check a source fact against its documentation

Search for how to pull a price history from Refinitiv in Python. Take the first two or three results you would plausibly have copied.

Now check them against LSEG's current documentation. Thomson Reuters became Refinitiv; Refinitiv was acquired by LSEG; the Python package was renamed. How much of what you found is still correct?

Bring what you found and how long the check took. That interval — how long it takes to confirm a source fact rather than assume it — is the habit this course runs on.

Part E — Write one paragraph

You have two sources for the same security and they disagree about one number. What would make you decide the disagreement is a defect in the data rather than a difference in convention? Give one concrete test you could run.

Keep it. You will compare it against what you learn in the session, and the comparison is part of Lab 1.

Bring to the session: a running notebook, your Generation 1 attempts, a Generation 2 key with something pulled, what your Refinitiv search turned up, and this paragraph.
