The two generations

This distinction is the spine of the course. It is not a ranking.

Generation 1 — institutional. Licensed, seat-bound or approval-gated, built for humans and for batch research. Deep history, survivorship-free, authoritative. Access is slow and procedural; the interface was never designed for a machine to drive.

Generation 2 — API-native. Key-based, metered, documented for machines, often with an MCP server. Access is instant and cheap. History is shallower, coverage narrower, and the vendor may be four years old.

An analyst in the AI era has to work both, and the skill is different in each.

LSEG Workspace — and CodeBook, the coding route

Researched against Purdue Libraries' own guides 2026-08-21. Owner is confirming the exact entitlement from library correspondence — treat the CodeBook line as strong inference, not established fact, until that lands.

What Purdue publishes (guides.lib.purdue.edu/refinitivworkspace):

ProductLSEG Workspace — company, industry, economic data, news, ESG, M&A, charting
EligibilityAll Purdue users. Register with an @purdue.edu address
RegistrationHandled by LSEG, not Purdue. Delays are normal; check the spam folder for the welcome mail
AccessWeb (recommended), desktop (adds an Excel add-in), mobile (not recommended)
Add-onsDatastream (time series), Aftermarket Research, SDC Platinum — see the Datastream entry below, it is not a programmatic route
Stated export limitDeals Screener: 200 deals per export, 1,000 per 24 hours, per account

The Purdue guide does not mention Python, APIs, or programmatic access anywhere. That absence is itself the finding: the coding route exists but is not advertised by the library.

CodeBook — the coding route inside Workspace:

WhatA cloud-hosted Jupyter/Python environment available as an app inside Workspace. Zero install
AuthPre-authenticated by your Workspace session — no separate key to manage
LibrariesLSEG data libraries plus common Python packages, pre-installed
RunsIn LSEG's cloud, in the browser. Not on your machine

Why this shape matters more than it first appears. With CodeBook, your code runs inside the vendor's sandbox rather than in your own environment. That is genuinely different from every Generation 2 source, where the code lives with you and the vendor just answers requests.

Consequences worth teaching directly:

  • No local install and no lab-machine dependency. It is a browser app, so it works from any

machine. My earlier claim that LSEG needed campus lab machines was wrong.

  • Your notebook lives in their environment. Version control, reproducibility, and handing

work to a colleague all become harder, and the Week 7 reproducibility standard has to account for it.

  • Getting results out is governed by export limits and licence, not by your code.
  • You cannot pip-install whatever you like. The environment is theirs.

That trade — convenience and pre-authentication in exchange for control over your own environment — is a real one analysts meet constantly, and it is the sharpest available contrast with the Generation 2 model.

Not what Purdue has, so do not build against it: the locally installed LSEG Data Library (pip install lseg-data, import lseg.data as ld) driving a Workspace desktop session. Name it in Week 1 as the fuller commercial product; nothing in this course depends on it.

Datastream at Purdue — Excel only, and that is the point

Verified against guides.lib.purdue.edu/refinitivworkspace/datastream, 2026-08-21. Owner flagged this correctly: it is an Excel add-in, not a Python route.

What100+ years of historical time series — equities, indices, economics, FX
AccessExcel Add-In (appears as a "Workspace" tab in the Excel ribbon after installation), plus web
Python / R / APINone described by Purdue. No DSWS, no DatastreamPy, no programmatic path
Download limits30,000 values per download request; 2,000 suggested for historical instrument codes
EligibilityLicences are limited — faculty, graduate students, and those working directly with faculty on research. MSF students qualify, but the seat is scarce
How to get itTwo steps: obtain a Workspace account first, then email the library to request the add-on
Retention"Licences may be removed at any time due to inactivity"

Do not present Datastream as scriptable at Purdue. An earlier draft of this register suggested a Datastream Web Service route; that was wrong for our entitlement and is corrected here.

Why this belongs in the course rather than being quietly dropped. Datastream is Generation 1 at its most extreme, and it makes the point better than WRDS does: a century of excellent data, reachable only through a spreadsheet, on a scarce licence that expires if you stop using it.

You cannot put an AI on it. Not because the AI is inadequate — because there is no interface for one. That is a real and common constraint, and the professional response is not to complain about it but to use the source for what it is uniquely good at, export within the stated limits, and document what you did by hand so someone else can repeat it. A manual extraction with a written procedure is reproducible. A manual extraction with no record is not.

Teach it as: reach for Datastream when you need long history nobody else has, and accept that the cost is manual work and a written procedure instead of a script.

Diagnose your own entitlement in five minutes — do not wait for a reply

The registration welcome mail points at everything needed to answer this yourself. This is the procedure; it is also a graded readiness step, because self-diagnosing an entitlement is the professional skill.

1. Sign in to Workspace web — workspace.refinitiv.com/web, with the @purdue.edu User ID from the welcome mail.

2. Search the app bar for APPKEY — the App Key Generator. It is reachable from the web version, not only desktop.

  • If it opens and offers Register New App, note **which APIs appear in the selectable

list**. That list is the entitlement answer, directly, without asking anyone.

  • If it does not appear, API access is not enabled on the account.

3. Search the app bar for CODEBOOK — if it opens, the hosted Python environment is entitled.

4. Open MyAccount — the welcome mail describes it as where you "view product, data and exchange information." This is the authoritative record of product, data, and exchange entitlements, and it decodes the package label shown on the account.

Reading the result honestly — three separate things, routinely confused:

What it isLikely on an academic licence
App Keyidentifies your application. Created in APPKEYOften available
Session typeDesktop Session needs the Workspace desktop app running (it listens on a local port), so no Colab. Platform Session uses cloud credentials — Machine/Service ID and secretDesktop plausible; Platform is usually a separate enterprise entitlement and commonly absent
Content entitlementswhich data you may actually pull — estimates, transcripts, real-timeSeparate again. Having a key does not grant content

An App Key is not the same as data access. A student can hold a valid key and still be refused the content. Check all three, and record what each says.

Workspace web is confirmed available to every Purdue user and carries the hands-on work. The entitlement inquiry itself becomes a graded readiness item — the student sends the questions and reports what came back, including nothing.

Why this is worth teaching rather than working around. "What does my licence actually permit?" is a real professional question that routinely has no fast answer. The competent behaviour is to ask precisely and in writing, keep a record, and design so you are not blocked while you wait. Students who learn only that data is available by typing a ticker have not met the constraint that governs most institutional work.

The LSEG MCP connector — the frontier, and the same gate

LSEG announced an MCP connector for ChatGPT on 2025-12-03, live from that December, phased in starting with LSEG Financial Analytics. It lets a user with LSEG licensed credentials pull market data, analytics, and news directly into ChatGPT.

Two things students should take from it:

  1. The direction of travel is real. Financial Datasets ships an MCP server. LSEG now ships

one for ChatGPT. Professional vendors are making themselves addressable by agents, and this is a genuine change in what an analyst's day looks like.

  1. The gate did not move. It still requires licensed credentials, and whether an

institution's licence includes it is the same unanswered question as above. An MCP connector does not dissolve an entitlement problem; it inherits it.

Treat this as a demonstration and a discussion, never a dependency.

The teaching asset survives whichever product it turns out to be. LSEG absorbed Refinitiv, which absorbed Thomson Reuters, and the Python package was renamed refinitiv-data → lseg-data. Ask an AI for Refinitiv or LSEG Python code and check the package name, import path, and field names against current documentation. The student runs the experiment; the result is the lesson.

Bloomberg — not used in this course

Terminal-seat-bound. There is a blpapi interface, but it requires a live authenticated terminal session on the same machine, which makes it unusable for coursework and unusable for most reproducible analysis.

Removed from the required list entirely (owner ruling 2026-08-21). Named once, in Week 1, so students can say why — being able to explain that you cannot build a pipeline on it is the capability. Nothing in this course depends on it.

Generation 2 — API-native, AI-era

Purdue does not supply these. You obtain your own keys. All are usable at low or zero cost at course scale — but check the current cost yourself before signing up. These vendors change pricing often, and this page may be out of date by the time you read it.

Course policy

Guaranteed lane: SEC EDGAR direct, plus yfinance and FRED for prices and macro. Every graded task is completable here alone, at zero cost, with no account.

Institutional lane: WRDS and LSEG. Students pursue access; whoever gets it uses it. Access is never worth points — the documented attempt and what it taught them is.

API-native lane: students obtain keys where the free tier or credits allow. Any spend must be optional and trivial; a student who spends nothing is never disadvantaged.

Cost ceiling: no graded task may require a student to pay. Where a paid source appears, it appears as a demonstration or an optional enrichment, and the free equivalent is named beside it.

What AI gets wrong about each of these

The course's recurring lesson. Failure modes differ by generation:

SourceThe characteristic AI failure
WRDSInvents plausible table and column names. The schema is not reliably in the model
LSEG Workspace / CodeBookGenerates the retired refinitiv-data package and old import paths
DatastreamWill happily write DatastreamPy code for an entitlement Purdue does not have. There is no Python route here at all
SEC EDGARUsually correct on endpoints; often omits the required User-Agent header
DatabentoConfuses schemas and datasets; may assume the wrong symbology
Financial DatasetsGenerally good — the MCP server means the model is querying, not recalling
Any of themStates a coverage window or a price with total confidence and no basis

The transferable rule: an AI's knowledge of a data source is a claim, not documentation. Verify the package name, the endpoint, and the schema against the vendor's current docs before you trust generated code. That check takes two minutes and it is the difference between working code and a plausible-looking failure.
